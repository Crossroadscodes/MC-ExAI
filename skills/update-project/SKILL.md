# ExAI 更新流程

默认项目为 `D:\software\MC\OpenProject\ExAI`，远程仓库为 `Crossroadscodes/MC-ExAI`。默认发布附件来源为 `D:\software\MC\SparkServer-2\plugins\ExAI.jar`；用户指定其他项目或路径时以用户指令为准。

## 准备版本和说明

- 检查仓库规则、Git 状态、当前分支、远程地址和现有 Release。提交项目改动，保留无关本地文件，不把服务器配置、凭据或临时实施计划纳入提交。
- 读取 `pom.xml` 的项目版本和待发布 JAR 内的 `plugin.yml`。源码 `plugin.yml` 使用 `${project.version}`，由 Maven 资源过滤填入版本。Git 标签不会修改 JAR。
- 发布版本、POM 版本、JAR 内部版本、README 徽章和发布链接必须一致。发现不一致时，先修正源码版本并重新打包；用户指定现成服务器 JAR 时，不擅自用本地构建替换，也不直接修改压缩包伪造版本，等待匹配的产物再发布。
- 用户提供的更新要点必须同时出现在中文和英文发布说明中。同步更新 `README.md` 和 `README_EN.md` 开头的最新版本说明、版本徽章及 Release 链接，译文与原文含义一致。

## 验证、提交和发布

- Java 或资源变化运行 `mvn test package`；仅版本和文档变化时运行打包检查。检查差异与必要的测试结果，说明实测范围；源码测试通过不代表指定服务器 JAR 已经过同样测试。
- 记录指定 JAR 的 SHA256、文件大小和内部版本。先将附件复制到临时目录形成固定快照，再验证和上传该快照，避免服务器目录中的文件在发布期间变化。
- 使用 Conventional Commit 提交任务相关文件，推送当前目标分支。不要强推。使用 `git rev-parse HEAD` 的完整提交哈希作为 Release 的目标。
- 新版本创建 `v<版本>` 标签及正式 Release，标题为 `ExAI v<版本>`，附件名 `ExAI.jar`。发布说明分别列出中文与 English 更新内容。
- 用户要求替换刚重新打包的同版本时，更新已有 Release，不另造版本。先上传新附件为临时名称，验证成功后再移除旧附件并将新附件重命名为 `ExAI.jar`；尽量缩短无附件窗口。若工具只支持覆盖，保留旧附件临时备份后再覆盖。
- 已有标签不能因为补交文档或版本提交而擅自强制移动。补充提交照常推送；报告发布标签是否仍指向先前提交。已存在标签时，修改 Release 的 target 参数不会移动 Git 标签。
- 发布说明通过 UTF-8 临时文件和 `--notes-file` / `--body-file` 传递，保留真实换行。失败后先读取远程状态，再有针对性地重试，避免重复创建 Release 或上传重复附件；权限失败使用环境规定的审批机制。

## 收尾

检查 Release 已正式发布、说明含中英文、附件名和大小正确，并将远程附件摘要与本地 SHA256 对比；若服务不提供摘要则下载后校验。检查远程分支与推送提交一致。最终给出提交哈希、Release 链接、验证结果及任何版本或标签限制。
